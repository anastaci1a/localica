Documentation map

Each topic has one authoritative home. Product, Interface and Structure describe the checked-out branch's contracts. They do not establish that every behavior is verified or released.

Document Owns
Product Scope, library and queue semantics, file safety, lyrics sources and statistics.
Interface Layout, gestures, navigation, selection and UI defaults.
Structure Code boundaries, persistence, concurrency, rendering and technical constraints.
Roadmap Proposed outcomes and deferred capabilities.
Build Verification, compatibility, signing, release preparation, previews and documentation publishing.
Documentation standard Public prose, ownership of facts, status labels and review criteria.
Working instructions Contributor workflow, issues, labels and commits.
Collaboration Responsibility, integration and handoffs.

The root README introduces the app. Issues own actionable work and acceptance criteria. Releases identify distributed builds. Git and PR evidence retain history and tested revisions.

Before integrating a component PR, inspect ancestry, diffs and exact-source evidence. An open PR may already be included in a cumulative branch.

Archived records under docs/project-history/ preserve historical evidence. They are outside the maintained contract and website inventory.

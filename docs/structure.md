# Technical structure

One Kotlin/Compose `app` module with constructor injection. Keep storage/playback independent of Compose and graphics; introduce interfaces or modules only for demonstrated boundaries. Toolchain and format compatibility belong in [Build](build.md); behavior belongs in [Product](product.md) and [Interface](interface.md).

## Code map

Paths below are under `app/src/main/java/io/github/anastaci1a/localica/`.

| Package | Responsibility |
| --- | --- |
| `library`, `browse` | Document access, indexing/Room, shared queries, grouping, filters and view preferences. |
| `scanner`, `editing`, `lyrics` | Background scans, recoverable writes/image selection, local lyric discovery/parsing. |
| `queue`, `playlist` | Durable occurrence-based collections and serialized commands/imports. |
| `playback`, `statistics` | Media3 service/controller, elapsed listening, durable qualified events. |
| `navigation`, `home` | Restorable typed routes/preferences; typed pins and manual order. |
| `ui` | Compose views, lifecycle-aware state, gestures and reusable materials. |

`app/src/test` holds fast behavior tests; `app/src/androidTest` covers real Android storage, UI and playback. Source code owns schema numbers, dependency versions, cache sizes and other tunable constants; docs retain their constraints and rationale.

## Persistence and commands

- **Library:** identity is provider authority + document ID; root membership stores access URI and relative path separately. Identity across moves/renames depends on the provider retaining its ID. Scans transactionally replace one root; failure/cancellation preserves its prior contents and other roots. Metadata failures keep filename fallbacks and per-root paths until a successful rescan. Release a removed root's grant after commit; try retained alternate grants for playback.
- **Queries/navigation:** run complete deterministic queries off Main; pass the full displayed occurrence list and selected index to queue creation. Typed tab stacks, route keys and Compose saved state retain browse positions. React to requested filters immediately, cache a bounded set of completed presentations, and publish style/results atomically; wait for matching results/layout before restoring or resetting a list. Future paging must preserve complete queue snapshots and occurrence identity.
- **Playlists/queues:** Room entries have independent occurrence IDs and shared track snapshots. Controllers serialize transactional edits; cursor-only updates avoid rewriting entries. Listening visits and planned cycle membership use separate typed rows, with changes stored incrementally; ordinary position checkpoints leave them untouched. Playlist imports are bounded to 5 MiB/20,000 entries and commit after review. Preserve released database migrations, IDs, references, grants and settings; missing snapshot fields remain unknown.
- **Playback:** only `MediaSessionService` owns/attaches ExoPlayer; UI and system transport use the same QueueController command channel/timeline. Start queues before persisting their full contents; loaded-queue selections seek without rebuilding or querying. Serialize writes and recover/retry from the durable snapshot. Capture cursors on events, every five seconds and at service destruction; abrupt termination restores the last committed checkpoint.
- **Traversal:** QueuePreferences owns global modes; import legacy active-queue modes once and leave compatibility columns inert. Feed a bounded window of tokened visits into Media3, independently of visible queue order. The saved sequence already incorporates shuffle; Media3 uses identity shuffle order. Capture every native arrival immediately, including while storage is busy; finish the callback batch before extending the timeline, then persist.
- **Statistics:** The service measures monotonic playing time; serialized statistics writes retry stable event IDs without double counting. A separate database prevents collection deletion from deleting play history. Rules: [Product](product.md#dates-and-listening-statistics).
- **Settings/selection:** use typed preference boundaries with explicit inheritance. Session selection retains source occurrence IDs; successful commands report completion before it clears. Pins keep typed identity/manual order independently of tabs.

## File operations

Use persisted Storage Access Framework tree grants without broad storage permission. Enumerate off Main; never assume document IDs are filesystem paths. Scans and tag writes share a file-operation lock.

- Scanner work belongs to an explicit `dataSync` foreground service with bounded wake lock, progress/cancellation and app-owned state. Survive Activity recreation/backgrounding, honor service timeouts, and report process interruption next launch. Notification permission is optional; expose the closest app-specific settings destination when controls/restrictions need attention.
- Tag writes run under a `dataSync` foreground service with a bounded wake lock; the Activity may dismiss the editor while work continues. Keep the last eight job outcomes locally and mark unfinished jobs interrupted on process restart. Stop requests finish the current verified write.
- Edit a private copy with Jaudiotagger; compare encoded audio/unrelated tags and verify requested values/artwork before overwriting. An atomic journal and synced original precede the write. On failure, attempt verified rollback; retain recovery until library/playlist/queue refreshes complete. Interrupted recovery is available in Settings.
- Before editing any active-queue file, capture occurrence/cursor/playing state and release prepared sources, including duplicates. Rebuild/restore after completion or recovery. Inactive-queue edits leave playback intact. Natural advancement keeps one prepared timeline; obsolete preparations are invalidated and preparation failures leave current playback intact.
- Verified writers cover MP3/M4A/FLAC/Ogg Vorbis/WAV. Unsupported fields/formats/nonseekable providers remain read-only. Supplement platform tags through granted seekable descriptors: bounded ID3 reads, tag-only FLAC/Ogg views and sparse MP4/WAV views avoid copying audio. Cap supplementary metadata at 16 MiB; delete temporary views after use/startup. RF64 supplementary tags remain unsupported.
- Bound/orient imported images; the zoom viewer decodes separately. Resolve lyric sidecars through tree children + indexed relative folder; bound lyric inputs to 2 MiB/10,000 lines. Media3's Vorbis-comment reader covers Opus. Source choices persist per song.

## Rendering and gesture boundaries

- A replaceable cover provider uses a bounded cache, including missing-cover results, and cancellable serialized reads. Choose collection covers in stable identity order; size decodes to their display. Rescans/edits invalidate artwork and lyric caches. No scraping. Read cached covers synchronously for the first frame, retaining smaller same-identity covers while larger decodes load. A recycled row never retains another identity's image; the player retains its previous completed artwork/palette until the next pair is ready.
- One player expansion progress controls persistent artwork/title/transport geometry and masks. Scale fixed-size glyphs; do not step font sizes. Prepare and cache bounded current/neighbor artwork bundles, including soft cover edges, off Main. Expansion shares one corner geometry between clipping, refraction and rims; older Android blends prepared blur endpoints without per-frame bitmap work. Blend cover and color continuation together, flattening the displayed composite only when interrupted; reuse prepared textures during gestures. Scroll toward continuously measured destinations to avoid overshoot/correction passes.
- Keep gesture ownership until release. Artwork has diagonal priority over the parent’s clearly vertical recognizer. Pinch transitions retain a bounded set of visible source drawings until release so virtualization cannot erase a reversed preview. Drag-stack cards use one display-frame update and bounded absolute positions; apply drawing-layer translations without per-frame content recomposition/measurement. Edge scrolling uses elapsed frame time. Keep stack, cancel target and list clipping in separate foreground layers.
- The theme owns modal lifetimes, preserving caller state/locals through exit. Restore caller locals before creating each window so its view/focus owner stays correct; nested windows sample the completed parent panel. Measure glass from foreground content, then fit its padded backdrop independently.
- Shared Liquid Glass controls and the frosted Queue drawer filter only their backdrops. Separate recordings of browsing content, panel material, lists, player and lyric backgrounds prevent sampling cycles; foreground icons/text stay crisp except inside explicitly composite selection lenses. Connected media lenses record their content before adding a shallow perimeter distortion; the optional navbar overlay records the finished bar and labels, excluding the overlay itself. Modal windows alone may sample the complete screen, aligned through global coordinates; inline lenses use recordings that exclude themselves. Keep composed backings within their viewport. Glass uses padded AGSL rounded-surface refraction on Android 13+ and edge lighting on older versions. Backdrop blur is live on Android 12+; Android 8–11 prepare shared, cancellable snapshots after scene changes and settled scrolling, never on each gesture frame. Modern adaptive tint evaluates local background brightness in the shader without GPU readback; older versions reuse their settled snapshots. Glass blur strength is independent of the denser drawer material; tint stays below foreground content and floating shadows exclude the transparent interior. Guard unrecorded/released layers before readback. Graphics remain replaceable and independent of core data/playback.

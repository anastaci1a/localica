# Structure and decisions

Use one `app` module and ordinary constructor injection. Extract modules only when a real boundary needs it; avoid committing to a framework for dependency injection or navigation at this size.

| Location | Responsibility |
| --- | --- |
| `app/.../library/` | Track models, recursive scanning, Android document access, Room persistence, shared queries, grouping, and per-view preferences. |
| `app/.../playlist/` | Durable manual playlists, bounded local imports, independent occurrence identities, and serialized edits. |
| `app/.../scanner/` | Foreground scanning service, app-owned progress/cancellation, and scanner preferences. |
| `app/.../queue/` | Persistent listening sessions, entry identity, serialized commands, and typed listening settings. |
| `app/.../playback/` | Media3 service and controller; the service owns the player independently of screens. |
| `app/.../navigation/` | Typed per-tab routes, saved-state codec, Back history, and interface preferences. |
| `app/.../browse/` | Shared collection/search results and list-type presentation/sort preferences with collection overrides. |
| `app/.../home/` | Durable typed pins and their manual ordering. |
| `app/.../editing/` | Checked-field tag patches, verified format writes, durable recovery, batch outcomes, and image selection. |
| `app/.../lyrics/` | Local embedded/sidecar discovery, bounded lyric caching, LRC/SYLT parsing, source choice, and playback-position lookup. |
| `app/.../ui/` | Compose screens and a lifecycle-aware view model; renders immutable state and sends actions. |
| `app/src/test/` | Fast behavior tests using fake document sources. |
| `app/src/androidTest/` | Database, UI, and playback checks on Android. |
| `docs/` | Current product goals, structure, and milestone outcomes. |
| `agents/` | Working instructions and documentation maintenance. |

## Baseline

- Kotlin, Compose, Android 8+ (API 26), compile/target API 36, JDK 17, and a pinned Gradle wrapper. The minimum supports modern storage and media APIs without excessive compatibility branches.
- Media3 ExoPlayer and a MediaSessionService provide local playback, audio focus, headset disconnection handling, and system controls. The service attaches its player to the queue command gateway; app transport and queue edits share a serial command channel. System controls use the same Media3 timeline. No decoder extensions or network permission. MP3 and AAC in M4A are primary targets; WAV, FLAC, Ogg/Vorbis, and Opus use device decoders where available. See [supported formats](https://developer.android.com/media/media3/exoplayer/supported-formats).
- The [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files) grants read access to user-selected folder trees without broad storage permission. Persist each grant, enumerate off the main thread, and rescan roots independently. Unsupported root locations follow the system picker's restrictions.
- Library Room schema 5 includes richer tags and persistent per-root metadata failure markers, with in-place migrations from the released single-folder database. Metadata belongs to a track identified by provider authority and document ID; each root has its own membership, access URI, and relative path. Overlapping roots share a track. Identity survives rescans and alternate root access, but depends on the provider retaining its document ID across moves or renames.
- A scan commits one root transactionally. Failed/cancelled scans preserve its last successful contents and all other roots. Metadata failures retain a filename fallback and their per-root paths until a successful rescan. Removing a root releases its grant after database commit and never deletes audio files. Missing permissions leave indexed tracks visible; playback tries another retained grant when available.
- Scanning runs in an explicit `dataSync` foreground service with a bounded wake lock, notification progress/cancellation, and app-owned state. Notification permission is optional; explain missing drawer controls and background restrictions through app-specific Android settings links. Activity recreation and backgrounding retain the scan. Cancellation preserves the current root; process interruption is reported next launch. Honor Android’s service timeout and stop cleanly. Scanner preferences cover subfolders, minimum known duration, excluded relative paths, and opt-in launch scanning. Folder selection only configures access; manual scanning lives in the scanner dialog.
- Shared queries return complete, deterministic ordered song rows using text search, root filtering, and metadata sorting. Work runs off the main thread. Search text and filters belong to saved routes; typed preferences retain ordering/presentation by list type with optional collection overrides. Album catalogs and album contents are distinct types. The full displayed song result and selected occurrence index supply new queue snapshots, including duplicate playlist occurrences. Large-library paging and indexed search remain future optimizations.
- Navigation retains independent tab stacks and visit history, with route-keyed Compose saved state for scroll positions. Fresh launch prefers Home; activity recreation restores the current route. One animation progress controls the expanding player surface and tab shelf. Playback requests expand the player only for actions that start playback, subject to the user's preference. Back dismisses overlays before returning through browsing history; closing the Activity leaves the service running.
- A separate Room playlist database stores named collections and ordered entries. Entries share the queue snapshot codec, with unique occurrence IDs independent of library membership. PlaylistController serializes transactional edits and publishes committed state. Rescans refresh displayed metadata by track ID; unavailable files retain their stored references. Search and sorting preserve occurrence IDs and never rewrite manual order. Local M3U/M3U8/PLS imports resolve only against indexed songs, preserve duplicates/order, and preview ambiguous or missing entries before a transactional save. Bound input to 5 MiB/20,000 entries; never fetch URLs.
- A separate Room queue database stores named queues, ordered entries, and the active queue. Entries have unique IDs and serialized track snapshots, independent of library rows, so duplicate songs and removed roots are preserved. Metadata-only cursor writes avoid rewriting entry lists. Creation, cleanup, and edits commit transactionally before the player changes.
- QueueController is an in-process gateway shared by the app and service; only the service attaches a player. It serializes commands, refreshes available document locations, and applies Media3 playlist edits without restarting the current song. Capture the cursor on player events, every five seconds, and on service destruction. Abrupt termination restores the last committed checkpoint. Restore paused; never autoplay on launch.
- SharedPreferences stores typed song-tap, queue-switching, and optional count-limit settings. Queue state exposes observable settings to screens. Each song-list scope has an optional tap override with explicit inheritance/reset. Selection actions bypass tap preferences and insert complete batches in displayed order.
- Embedded covers load on demand through a replaceable cover provider. A 12 MiB memory cache shares covers and missing-cover results; cancellable serialized requests prevent scrolling from flooding readers. Decode at 128/384/768-pixel bounds according to display size, and invalidate on successful rescans or edits. Collections try member tracks in stable identity order; absent, invalid, or oversized artwork uses a placeholder. [Media3 Inspector](https://developer.android.com/media/media3/inspector/retrieve-metadata) supplements platform tags with comments and format-specific tag mappings. Tagged MP3, M4A, FLAC, Ogg, and Opus fixtures cover the requested text fields.
- Catalogs, playlists, and queues share browsing templates, scoped search, list/gallery presentation, sorting, and contextual selection. Display sorting never rewrites saved order. Selection survives dismissed menus, canceled confirmations, and failed saves; successful commands report completion before clearing it. Typed pins preserve song/album/playlist identity and manual order independently of tabs.
- Tag edits use Jaudiotagger on a private copy, compare encoded audio and unrelated tags, and verify requested values/artwork before writing a document. An atomic journal and synced original copy precede the overwrite; a failed save attempts a verified rollback. Interrupted edits retain recovery in app storage and can be restored from Settings. Keep that copy until library, saved playlist, and queue metadata refreshes complete. Scans and edits share a file-operation lock. The current song pauses during its edit and restores its queue entry/position afterward.
- The editor modifies only checked fields; blank checked fields remove tags. Batches deduplicate song identities, report per-file results, and can stop after the current transaction. Folder write grants are requested explicitly. MP3/M4A/FLAC/Ogg Vorbis/WAV writes are verified; unsupported formats, fields, and nonseekable providers remain read-only. Supplementary tags use granted seekable descriptors directly: bounded ID3 reads and temporary tag-only FLAC/Ogg views or sparse MP4/WAV views preserve offsets without copying audio payloads. Temporary views are deleted after use and on startup; metadata is bounded to 16 MiB. RF64 supplementary tags are not yet supported; platform metadata remains available. Artwork selection uses bounded, orientation-corrected images, optional recent-photo access, and a system picker fallback; the viewer decodes separately up to 2048 pixels.
- Lyrics are read only when needed, with a 4 MiB cache invalidated by the same scan/edit revision as artwork. Matching sidecars are resolved through document-tree children and the indexed relative folder, without assuming document IDs are paths. LRC supports offsets and repeated timestamps; ID3 SYLT supports millisecond timing and supported text encodings. Embedded plain/LRC text uses container tags, with Media3's Vorbis-comment reader covering Opus. Frame-count SYLT timing remains unsupported and is reported. Inputs are bounded to 2 MiB/10,000 lines; available plain text remains selectable.
- Artwork gestures use independent persisted actions. The lyrics panel crossfades within the player, follows playback using timestamp lookup, and fades viewport edges with a local alpha mask. Manual dragging releases following; a button restores it. Touch exploration starts with following off. Source choices persist per song; Back closes lyrics before collapsing playback. Motion settings govern fades and lyric scrolling. These components use ordinary materials ready for later glass styling.

## Planned foundations

Evolve the current module through explicit library-query, queue-command, settings, and tag-writer boundaries with constructor injection. Keep storage and playback logic independent of Compose. Add interfaces at these real boundaries as they become necessary.

- Library and queries: retain complete-result queue snapshots and independent occurrence identities if the UI later adopts paging. Tag changes must refresh grouping and saved references without losing playlist or queue identity.
- Settings: extend the typed preference boundaries as capabilities arrive. Defaults and user choices are part of the product contract, not scattered screen logic.
- Tags: extend format/provider support only with recoverable writes and round-trip verification. Keep per-file outcomes and the format/document-access boundary; a failed write must not be presented as a successful library update.
- Presentation: implement a reusable Compose design system inside the app first. Glass rendering must not become a dependency of scanning, playback, or persistence. API 26 remains supported through solid-material fallbacks; Android blur APIs have newer platform requirements.

Verification includes v1 migrations, failed/cancelled scans, multiple roots, deterministic queries, durable queue identities and positions, mixed-value batch edits, storage failures, and accessibility. Physical-device feedback supplements CI before major visual work.
